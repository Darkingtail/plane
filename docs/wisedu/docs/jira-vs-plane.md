### 1.5 AI 原生开发工作流（Plane 独有优势）

盗版 Jira 在此维度没有任何可比性，这是 Plane 对未来研发范式的根本性领先。

Plane 原生支持 MCP 协议（`plane-mcp-server`，55+ 工具），AI 编码工具可直接读写任务数据，这使得**全链路 AI 开发工作流**成为可能：

```
需求录入 → 需求分析 → 需求实现 → 需求验证 → 需求测试
  AI 生成      AI 拆解     AI 编码     AI 回写      AI 验收
```

| 阶段     | 传统方式            | Plane + AI                            |
| -------- | ------------------- | ------------------------------------- |
| 需求录入 | 人工填写 Issue      | AI 对话式录入，自动结构化为 Issue     |
| 需求分析 | 人工拆分子任务      | AI 读取 Issue，自动拆解 Sub Work Item |
| 需求实现 | 开发者手动编码      | AI 领取任务、编码、提交 MR，全程自动  |
| 需求验证 | 人工 Code Review    | AI 回写 Issue 状态、评论实现摘要      |
| 需求测试 | 人工测试 + 回填结果 | AI 生成测试用例，执行后自动更新 Issue |

**为什么必须是 Plane**：盗版 Jira 的 API 黑盒、无 MCP 支持，使得任何 AI 工具都无法稳定接入。Plane 的开放 API + 官方 MCP Server 是这条路线的必要基础设施。

## 三、替代必要性论证

### 3.1 继续用盗版 Jira 的代价

**合规风险（最高优先级，无法通过技术手段消除）**

使用盗版软件违反《计算机软件保护条例》。随着公司业务发展、对外商业合作增多，尽职调查中发现盗版使用将直接影响融资、合作和上市进程。这是一颗定时炸弹，且风险随公司规模增长线性放大。

**技术债务已到临界点**

jirascripts 与盗版 Jira 强耦合，任何扩展都需要在黑盒 API 上摸索。自建看板（jirascripts 前端工程）走到一半就遇到了这个天花板——数据源不可靠，边际价值递减。继续投入这条路，是在一个会死的地基上盖楼。

**系统已经在影响日常效率**

服务器卡顿、页面死掉不是偶发问题，是盗版系统无人维护、无法升级的必然结果。随着时间推移只会更差，不会自行好转。

### 3.2 现在切换的时机成本最低

- **Plane 提供完整 GitLab 自动化能力**，gitlab-bridge 可完整替代 jirascripts
- **Plane + opencode + MCP 开发工作流**已可接入，AI 辅助开发直接可用
- **团队已有 Plane 使用基础**，迁移学习成本低
- **历史数据可以归档不迁移**，不需要大规模数据搬迁

### 3.3 结论

| 维度 | 结论                                                  |
| ---- | ----------------------------------------------------- |
| 合规 | 必须替换，无选项                                      |
| 能力 | Plane 在可视化、AI、API、稳定性上全面超出盗版 Jira    |
| 不足 | 自定义字段、Epic 等缺口有明确解法，且都在可控工作量内 |
| 时机 | 现在是切换成本最低的时间窗口                          |
| 建议 | 新迭代直接在 Plane 发起，正式宣告 Jira 退役           |
