# Tracking — 源码改动追踪

[TOC]

> 记录所有对 Plane CE 上游源码的定制改动，升级时逐条 diff 对照。

---

## 用途

每当我们修改 Plane 原始源码（不是新增独立文件，而是改动上游已有代码），都必须在此记录。目的是：

- 合并上游新版本时，快速定位可能产生冲突的文件
- 评估冲突的处理方式（保留我们的改动 / 采用上游新实现 / 合并两者）
- 防止改动在多次合并后"消失"而不自知

## 与 sync/ 的关系

| 目录        | 视角     | 记录什么                             |
| ----------- | -------- | ------------------------------------ |
| `sync/`     | 上游视角 | 上游每个版本发了什么，我们是否已合并 |
| `tracking/` | 我们视角 | 我们改了上游哪些文件，改了什么       |

合并上游时，两者配合使用：`sync/` 告诉你上游改了什么，`tracking/` 告诉你我们改了什么，交叉比对才能准确判断冲突风险。

---

## 记录规范

每条改动包含：

- **目的**：为什么要改
- **关联 commit**：改动对应的 git commit
- **受影响文件**：逐文件说明改了什么
- **升级风险**：🟢 低 / 🟡 中 / 🔴 高
